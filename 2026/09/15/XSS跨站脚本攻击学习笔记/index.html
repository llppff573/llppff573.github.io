XSS跨站脚本攻击学习笔记

XSS 跨站脚本攻击

XSS基本概念和原理介绍

XSS（Cross‑Site Scripting）跨站脚本漏洞。
漏洞根源：服务端接收用户可控输入，没有做过滤与转义，将数据直接输出到前端HTML页面，浏览器会把用户输入当做JS代码解析执行。

攻击发生在受害者浏览器端，不是攻击服务器本身。攻击者可以实现行为：

  1. 窃取受害者Cookie会话凭证
  2. 伪造页面内容，实施钓鱼攻击
  3. 劫持页面DOM，读取页面敏感数据
  4. 配合其他接口发起请求

⚠️安全提醒：仅允许在自己授权的靶场环境练习，禁止对非授权网站做任何测试。

XSS三大类型

  1. 反射型XSS（非持久型）：Payload放在URL参数，数据不存入数据库，需要诱导用户点击恶意链接触发。
  2. 存储型XSS（持久型）：恶意脚本存入后端数据库，所有访问页面的用户都会触发脚本，危害等级最高。
  3. DOM‑XSS：完全由前端JS操作DOM渲染数据，后端不参与输出逻辑；抓包原始HTTP响应看不到Payload，仅在浏览器DOM树中生效。

从一个基础的反射性XSS来进一步认识XSS漏洞

反射型XSS‑GET

靶场位置：pikachu → XSS → 反射型xss(get)

  1. 用户输入的内容直接拼接在URL的GET参数中，页面回显输入内容。

  2. 输入基础测试Payload：<script>alert('xss')</script>，点击提交。

  3. 页面弹出alert弹窗，代表漏洞存在；观察浏览器地址栏，恶意脚本完整出现在URL参数中。

  4. 将完整构造好的URL发给受害者，受害者访问该链接即可触发脚本。

特点：数据不会写入数据库；必须诱导用户点击恶意链接。

反射型XSS‑POST

靶场位置：pikachu → XSS → 反射型xss(post)

  1. 通过POST表单提交数据，参数存放在HTTP请求体，不会出现在浏览器URL地址栏。

  2. 输入Payload：<script>alert('post xss')</script>，提交表单。

  3. 触发弹窗，证明漏洞存在。抓包可以看到恶意脚本位于POST请求体。

利用限制：无法直接分享URL，一般需要配合CSRF漏洞，构造恶意页面诱导用户自动提交表单。

存储型xss漏洞实验演示和讲解

靶场位置：pikachu → XSS → 存储型xss（留言板场景）

  1. 在留言输入框提交Payload：<script>alert('存储XSS')</script>。

  2. 提交页面直接弹窗；刷新页面、新开浏览器访问该页面依旧会弹窗。

  3. 原理：恶意JS代码存入后端数据库，每一位访问留言页面的用户，页面加载时读取数据库数据渲染页面，自动执行恶意脚本。

对比反射型XSS：不需要诱导点击特殊链接，只要访问页面就触发，危害更大。

dom型xss详解及多种场景演示

靶场位置：pikachu → XSS → dom‑xss

  1. DOM‑XSS执行逻辑：后端返回的原始页面不含恶意代码，完全依靠浏览器JS动态操作DOM，把用户输入拼入页面。

  2. 关键现象：Burp抓包查看HTTP响应源码，看不到注入的payload；打开F12开发者工具→【元素】面板，DOM树中才能看到注入的标签代码。

  3. 测试Payload：'><img src=x onerror=alert(1)>

  4. 页面触发弹窗；对比Raw响应包与F12元素面板。

注意：DOM‑XSS只做后端过滤无法修复，前端JS渲染逻辑同样需要做输入处理。
