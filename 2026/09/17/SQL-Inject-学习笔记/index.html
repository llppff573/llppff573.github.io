SQL‑Inject SQL注入学习笔记

SQL 注入(SQL‑Inject)

原理

用户输入可控，后端直接把用户输入拼接到SQL语句中执行，没有做过滤/预编译，攻击者可以闭合原有SQL语义，篡改SQL逻辑。

攻击发生在数据库层，直接操作后端数据库。

注入产生条件

  1. 用户输入可控
  2. 输入会拼接到SQL语句
  3. 后端没有使用预编译（PDO预处理）

常见注入分类

  1. 数字型注入 / 字符型注入
    数字型：参数无需引号包裹，直接拼接
    Payload：?id=1 or 1=1
    字符型：参数被单/双引号包裹，必须闭合才能篡改SQL
    Payload：?id=1’ or 1=1#
  2. 回显注入 / 盲注
  • 联合查询注入：页面直接返回数据（最简单）
  • 报错注入：利用数据库报错带出数据
  • 布尔盲注：页面只有正常/异常两种状态，无数据回显
  • 时间盲注：页面无变化，依靠 sleep() 延时判断真假
  1. 提交方式分类
  • GET 注入：参数在 URL 中
  • POST 注入：参数在请求体表单中
  • Cookie 注入：参数从 Cookie 获取拼接 SQL
