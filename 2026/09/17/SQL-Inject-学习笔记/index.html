SQL‑Inject SQL注入学习笔记

SQL 注入(SQL‑Inject)

原理

用户输入可控，后端直接把用户输入拼接到SQL语句中执行，没有做过滤/预编译，攻击者可以闭合原有SQL语义，篡改SQL逻辑。

攻击发生在数据库层，直接操作后端数据库。
⚠️安全提醒：仅允许在自己授权的靶场环境练习，禁止对非授权网站做任何测试。

注入产生条件

  1. 用户输入可控
  2. 输入会拼接到SQL语句
  3. 后端没有使用预编译（PDO预处理）

常见注入分类

  1. 数字型注入 / 字符型注入
    数字型：参数无需引号包裹，直接拼接
    Payload：?id=1 or 1=1
    字符型：参数被单/双引号包裹，必须闭合才能篡改SQL
    Payload：?id=1’ or 1=1#
  2. 回显注入 / 盲注
  • 联合查询注入：页面直接返回数据（最简单）
  • 报错注入：利用数据库报错带出数据
  • 布尔盲注：页面只有正常/异常两种状态，无数据回显
  • 时间盲注：页面无变化，依靠 sleep() 延时判断真假
  1. 提交方式分类
  • GET 注入：参数在 URL 中
  • POST 注入：参数在请求体表单中
  • Cookie 注入：参数从 Cookie 获取拼接 SQL

SQL 注入 整体总结（适配你当前 Hexo 博客笔记风格，放在全文末尾）

SQL 注入漏洞的根源是用户可控输入直接拼接进 SQL 语句执行，后端未使用预编译（PDO），攻击者可以通过构造特殊字符闭合原有 SQL 语义，篡改数据库查询逻辑，读取、修改甚至删除数据。漏洞发生在数据库层，是 Web 安全中高危漏洞。

  1. 按参数类型
    数字型：参数不带引号包裹，直接构造or 1=1即可；
    字符型：参数被单 / 双引号包裹，必须先闭合引号，再用#注释掉 SQL 剩余部分。
    搜索型：属于字符型变种，SQL 使用like '%xxx%'模糊查询，payload 需要适配%通配符。
    XX 型：SQL 被括号包裹，payload 需要同时闭合括号与引号。
  2. 按数据回显方式
    联合查询注入：页面直接返回查询结果，最简单，利用union select查询额外数据，要求前后查询字段数量一致；
    报错注入：页面输出数据库报错信息，借助updatexml()、extractvalue()、floor()等函数，把查询数据带入报错信息带出；
    布尔盲注：页面只有两种状态（存在 / 不存在），无报错、无数据回显，通过ascii()、substr()逐字符猜解数据；
    时间盲注：页面完全无变化，依靠sleep()结合if()函数，根据页面响应延时判断语句真假，适合完全无回显场景。
  3. 按提交位置
    GET 注入：参数放在 URL；POST 注入：参数放在表单请求体；Cookie 注入：参数从 Cookie 中读取；HTTP Header 注入：注入点在 User-Agent、Referer 等请求头，后端将 Header 内容直接拼接 SQL。
  4. 特殊注入：宽字节注入
    后端使用addslashes()转义单引号（'→\'），同时 MySQL 客户端编码设置为 GBK。GBK 为双字节编码，传入高位字节如%df，%df%5c会被 MySQL 解析成一个汉字，吃掉反斜杠，让单引号成功逃逸转义过滤。仅 GBK 环境存在，utf8mb4 不存在该漏洞。Payload 经典为%df' or 1=1#，sqlmap 可使用unmagicquotes脚本自动绕过。

拓展攻击手段

  1. 文件写入：满足secure_file_priv权限、知道网站物理路径时，使用into outfile写入一句话木马，获取服务器 Web 权限。
  2. 暴力猜解表 / 字段：Burp Intruder 爆破，结合exists()语句，通过页面响应差异判断表名、字段名是否存在。
  3. Insert/Update/Delete 注入：不止查询语句存在注入，增删改语句只要拼接用户输入，同样可以构造报错注入获取数据。

漏洞利用通用流程

  1. 探测：输入单引号'，观察页面是否报错 / 状态变化，判断是否存在注入、是字符还是数字型；
  2. 闭合：构造 payload 闭合原有 SQL 引号、括号，注释多余语句；
  3. 探测字段数：order by判断查询列数；
  4. 信息获取：查询数据库版本、当前库名、表名、字段；
  5. 脱库：读取账号密码等敏感数据；
  6. 拓展攻击：写入木马、读写文件（权限允许）。

防御方案

  1. 优先使用预编译（PDO），参数化查询，将 SQL 语句与用户输入完全分离，从根源杜绝注入；
  2. 统一数据库连接编码为utf8mb4，禁止使用 GBK，防御宽字节注入；
  3. 输入校验：采用白名单，严格过滤特殊字符，不要依赖addslashes这类简单转义；
  4. 最小权限原则：数据库账号只分配必要权限，禁止file_priv文件读写权限；
  5. 关闭前端数据库原生报错，屏蔽敏感报错信息；
  6. WAF 部署，拦截常见注入特征 Payload。

工具补充

手动测试使用 Burp Suite 抓包修改请求，Repeater 重复发包；sqlmap 为自动化注入工具，可一键探测、脱库，搭配 tamper 脚本完成各类绕过。仅用于本地靶场安全练习，禁止未经授权测试公网网站。
