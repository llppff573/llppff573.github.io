RCE学习笔记

RCE 远程代码执行漏洞

一、漏洞原理

RCE（Remote Command / Code Execution）远程代码/命令执行漏洞。
Web应用接收用户可控输入，直接把输入内容丢进系统命令或者代码执行函数，没有过滤、转义、白名单校验。
攻击者可以构造特殊字符拼接系统指令，在服务器上执行任意系统命令，获取服务器信息、读写文件、拿下服务器权限。

区分两个概念（笔记重点）

  1. 命令执行：调用操作系统命令（system()、exec()、shell_exec()等PHP函数），执行cmd/linux shell指令
  2. 代码执行：直接把输入当做编程语言代码解析运行（eval()、assert()、preg_replace /e）

核心一句话：用户输入被当成系统命令/后端代码执行，不是单纯字符串处理。

二、漏洞产生核心原因

  1. 业务需求需要调用系统命令，开发直接拼接用户参数
  2. 未对特殊符号过滤：| & ; $ ` ()
  3. 使用高危函数：system、shell_exec、passthru、eval、assert
  4. 黑名单过滤容易被绕过，仅黑名单防护不可靠

常用命令拼接符号（Windows & Linux）

符号 作用
; Linux：前面命令执行完，继续执行后面命令
` `
`
& Windows/Linux，前后命令都执行
&& 前面命令执行成功，才执行后面

六、漏洞危害

  1. 读取服务器任意文件：配置文件、数据库账号密码
  2. 写入文件，上传一句话木马，获取webshell
  3. 执行系统命令，接管服务器
  4. 横向移动，内网探测

七、防御方案

  1. 优先使用白名单：只允许指定内容输入（ping场景只允许ip格式）
  2. 禁用高危函数：php.ini 禁用 system、eval、shell_exec 等
  3. 输入过滤：对| & ; $ ` ()等特殊符号转义/拦截
  4. 使用安全API，不要拼接字符串调用系统命令，使用函数参数传参
  5. 最小权限运行web服务账号，即使被拿下，限制权限范围

八、实验踩坑记录

  1. Windows环境下ls不能用，要换成dir，容易报错无结果
  2. 管道符编码：GET提交时特殊字符浏览器会自动编码；Burp手动发包注意编码问题
  3. eval代码执行，payload末尾必须带分号，否则PHP语法报错不执行
  4. phpstudy PHP版本过高，部分危险函数默认被禁用，会导致payload无返回

九、对比总结（方便笔记复习）

  • CSRF：借用用户身份发起请求，不能执行命令
  • SQL注入：操纵数据库语句，只和数据库交互
  • RCE：服务器执行系统/编程语言代码，权限最高，危害最大
