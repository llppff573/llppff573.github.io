file Inclusion学习笔记

文件包含漏洞 超详细实验笔记（Pikachu靶场）

一、漏洞原理（通俗靶场版）

文件包含：Web开发为了代码复用，使用include、require、include_once、require_once等函数，接收用户传入的文件路径，加载并执行目标文件。
用户可控参数直接拼接到文件包含函数，没有严格过滤校验，攻击者可传入恶意路径，读取本地文件或者执行恶意文件。

核心一句话：后端把用户输入当做文件路径，直接加载文件内容并解析执行。

二、漏洞产生核心原因

  1. 使用PHP文件包含函数，变量可控，直接拼接路径
  2. 未对传入路径做白名单限制，黑名单过滤容易绕过
  3. 开启allow_url_include = On，可远程包含，危害更高
  4. 路径没有做限制，存在目录穿越（../）

四个核心函数区分

  • include：包含文件，找不到文件只抛出警告，脚本继续运行
  • require：包含文件，找不到文件直接致命错误，终止脚本
  • include_once：同include，文件只会加载一次
  • require_once：同require，文件只会加载一次

五、常见绕过方式

  1. 截断绕过（旧版本PHP，%00空字符截断，PHP<5.3.4）
  2. 点号过滤：....// 等价于 ../
  3. 路径编码绕过：URL编码 ../ → %2E%2E%2F
  4. 伪协议利用（重点！靶场高频考点）
  • php://input：POST传入PHP代码执行
  • php://filter 读取源码（最常用！） 读取php文件，base64编码输出，拿到源码，避免直接解析PHP。

六、漏洞危害

  1. 读取服务器任意本地敏感文件：配置文件、数据库账号密码、源码
  2. 配合文件上传漏洞，上传一句话木马，包含木马获取webshell
  3. 远程文件包含可直接加载远程恶意代码，拿下服务器
  4. 读取日志文件，注入代码，getshell（日志包含）

七、修复防御

  1. 白名单限制：只允许指定文件名，优先推荐
  2. 严格过滤../、\、http://等字符，禁止用户直接控制路径
  3. 关闭危险配置：allow_url_include=Off
  4. 文件路径固定前缀，限制只能在指定目录内读取
  5. 不要直接把用户输入传入include/require系列函数

八、实验踩坑记录

  1. 目录穿越层数不对：../数量不够，跳不出网站WWW目录，读取文件失败
  2. php://filter 读取php文件，不加filter会直接执行php而看不到源码
  3. %00截断仅低版本PHP可用，高版本已经修复，无效
  4. Windows和Linux路径分隔符不同：Windows支持/与\，Linux只用/
  5. allow_url_include默认关闭，大部分新版环境无法复现远程文件包含

九、漏洞对比

  • 文件包含：加载文件，文件内PHP代码会被解析执行，核心是引入文件
  • RCE：直接执行系统命令/PHP代码，不需要加载外部文件
  • SQL注入：操作数据库，和文件读取无关
  • XSS：在浏览器执行JS，只作用前端，无法读取服务器本地文件
