unsafe file Download and Upload学习笔记

一、漏洞综述

不安全文件操作漏洞分为 Unsafe File Download（不安全文件下载） 与 Unsafe File Upload（不安全文件上传），属于Web高频高危漏洞。成因是对用户可控文件参数、文件内容、后缀校验不严，攻击者可读取服务器敏感文件或上传恶意脚本，造成信息泄露、服务器被控制。

两者简单区分：文件下载是读文件；文件上传是写文件，实战中经常组合利用。

Unsafe File Download 不安全文件下载

原理:

后端直接接收前端filename/file/path参数，拼接路径读取文件，无目录限制与白名单，攻击者利用目录遍历（路径穿越）跳出业务目录，读取服务器任意本地文件。

  3. 常见绕过

  • URL编码：..%2F，双重编码..%252F
  • 斜杠替换：..\..\
  • 过滤替换绕过：....//
  • 00截断：../../etc/passwd%00.jpg（仅PHP5.3及以下有效）
  1. 修复方案
  2. 使用文件ID映射，前端只传ID，隐藏真实文件路径
  3. 固定基础目录，校验真实路径不能跳出指定目录
  4. 文件名白名单，只放行允许下载的文件
  5. 用户输入不能直接传入readfile、file_get_contents等读取函数

Unsafe File Upload 不安全文件上传

原理

上传功能未校验文件后缀、MIME、文件内容，攻击者上传php/jsp/asp等WebShell，访问文件即可执行恶意代码，获取服务器权限。

利用条件：上传恶意文件 + 文件可被解析执行

3.2 常见绕过

  • 黑名单绕过：php3、php5、phtml、jspx等后缀
  • 大小写绕过：Shell.Php
  • 00截断上传：shell.php%00.jpg（低版本PHP）
  • 图片马：copy 1.jpg+shell.php 2.jpg，配合文件包含执行
  • MIME绕过：抓包修改Content-Type为image/jpeg

3.4 修复方案

  1. 白名单校验，仅允许jpg/png/gip/zip等合法后缀
  2. 多重校验：后缀 + MIME + 文件头
  3. 文件上传后重命名，随机文件名+固定后缀
  4. 上传目录关闭脚本执行权限
  5. 文件存储到非web可访问目录

四、漏洞对比&联动利用

漏洞类型 行为 危害 核心条件
不安全文件下载 读取文件 源码/配置泄露 可控路径，无目录限制
不安全文件上传 写入文件 上传木马、代码执行 校验缺失，文件可解析

联动：上传图片马，借助文件下载/文件包含漏洞执行木马，拿到权限。
