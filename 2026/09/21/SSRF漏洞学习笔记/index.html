SSRF漏洞学习笔记

SSRF漏洞

一、漏洞原理

SSRF（Server-Side Request Forgery）服务器端请求伪造。
用户可控参数传入后端，后端服务器主动发起请求，且未对请求地址做过滤、拦截、校验。
攻击者可以伪造请求，让服务器访问自身、外网、内网主机，造成内网探测、端口扫描、读取本地文件、攻击内网机器等危害。

⚠️安全提醒：仅允许在自己授权的靶场环境练习，禁止对非授权网站做任何测试。
核心一句话：前端控制URL，后端替你发请求 = SSRF

二、漏洞成因

  1. 业务功能需要后端主动请求资源（图片下载、远程加载、URL预览）
  2. 请求的目标URL参数用户可控
  3. 后端未过滤 127.0.0.1、内网网段、文件协议
  4. 未禁用危险协议：file://、gopher://、dict://
  5. 没有开启内网IP黑名单、没有域名重定向拦截

执行流程

  1. 用户传入可控的 url 参数
  2. 后端服务器解析该地址，并由服务器自身发起网络请求
  3. 服务器访问外网/内网/本地文件
  4. 将请求结果返回前端
  5. 攻击者获取内网信息、文件内容、端口状态

漏洞危害

  1. 内网端口扫描、存活主机探测
  2. 读取服务器本地任意文件（配置、密码、源码）
  3. 攻击内网各类服务（Redis、Mysql、后台管理系统）
  4. 配合gopher协议可内网POST攻击、打内网机器
  5. 可进行内网漏洞探测、内网横向移动

常见绕过方式（面试高频）

  1. 本地绕过：127.0.0.1 → localhost、0.0.0.0
  2. 进制绕过：127.0.0.1 → 2130706433
  3. 域名跳转：指向自己的域名重定向到内网
  4. 协议绕过：过滤http，使用 file:// dict:// gopher://
  5. 短链接跳转绕过

防御方案

  1. 白名单机制：只允许访问可信外网域名
  2. 禁用所有危险协议：file://、dict://、gopher://
  3. 拦截内网IP：禁止 127.0.0.1、192、10、172 内网段
  4. 禁止域名重定向跟随
  5. 限制请求端口，只允许80、443

实验踩坑记录

  1. SSRF是服务器去访问，不是客户端，所以能访问内网资源
  2. file_get_contents 极易出现SSRF，是最常见漏洞函数
  3. 很多环境默认拦截内网地址，需要绕过
  4. 协议不同危害不同：http/https只能探测，file可读文件，gopher可打内网
  5. 与XSS区分：XSS是浏览器请求，SSRF是服务器请求

漏洞对比总结

  • XSS：前端浏览器执行，打当前用户
  • CSRF：借用用户身份发起请求
  • SSRF：服务器主动发起请求，打内网、打自己
  • 文件包含：读取本地文件（PHP解析）
  • SSRF：读取本地文件/扫描内网（网络请求）
