不安全的url跳转漏洞学习笔记

不安全的URL跳转漏洞

漏洞原理

不安全 URL 跳转（Open Redirect），也叫任意跳转漏洞。
业务页面接收用户可控的 URL 参数，后端直接跳转到该地址，没有做白名单校验、域名过滤。攻击者可以构造恶意跳转链接，诱导用户跳转到钓鱼网站、恶意页面。

核心一句话：可控跳转地址 + 无域名校验 = 钓鱼、伪装权威链接

漏洞成因

  1. 网页登录、退出、跳转功能需要传入 url/redirect/back 跳转参数
  2. 跳转目标地址完全由用户可控
  3. 后端未判断域名是否属于本站白名单
  4. 直接使用 header(location:)、js location.href 跳转外部域名

实验

  1. 打开对应界面，点击第三个链接，发现进行了跳转，可以修改url，传入一个url也会发生跳转。 访问后会自动跳转如百度的界面。也可以把url修改为恶意站点的url，并发送给用户，由于前面的部分是网站本身的，所以更容易被信任。
    后端部分： 通过get请求获取前端传来的url，如果url=i，会反馈：好的,希望你能坚持做你自己!；反之，就会进行跳转。应该对url进行白名单限制避免这个问题。

漏洞危害

  1. 钓鱼攻击：利用可信域名伪装链接，欺骗用户输入账号密码
  2. 诱导用户下载木马、恶意程序
  3. 配合社会工程学，提升诈骗成功率
  4. 影响网站公信力，被浏览器标记风险网站

常见绕过方式（面试高频）

  1. 协议绕过：http://、https:// 未过滤
  2. 前缀绕过：只判断 [http://localhost](http://localhost)，可构造 [http://localhost](http://localhost).evil.com
  3. 特殊字符绕过：\t \n、@ 符号绕过正则
  4. 相对路径绕过不严导致跳转外网

防御方案

  1. 域名白名单（最有效）
    只允许跳转到本站指定域名，禁止所有外部域名

  2. 严格正则匹配
    判断跳转地址必须以本站域名开头

  3. 禁止完整外网协议
    过滤 http://、https:// 外网协议

  4. 不直接使用用户参数跳转
    后端写死跳转路径，用户只能选择预设页面

漏洞对比总结

  • SSRF：服务器访问内网/外网
  • URL跳转：浏览器被带走跳转外网
  • XSS：页面执行恶意代码
  • 目录遍历：读取本地文件
  • 信息泄露：直接暴露敏感文件
